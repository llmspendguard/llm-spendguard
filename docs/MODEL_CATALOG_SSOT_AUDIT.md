## 1. Physical store and logical boundary

There are **64 models, 16 distinct top-level model fields**, seven vendor rows, four alias entries on three models, and **zero physical catalog SQLite files in this checkout**. Absence of the binary does **not** mean absence of a SQLite catalog. `912043b7` (2026-11-11, PR #315) deliberately introduced SQLite; `bc9efd42` added in-memory construction when the optional binary is absent. The reviewable authoring input remains `store/reference_data/model_catalog.json`; `catalog_seed.sql` is its generated, committed deployment representation. Runtime executes the seed into an in-memory SQLite database and serializes/decodes that database when no binary exists (`catalog_store.py:244–276`). Thus the user's SQLite understanding reflects implemented intent, not a lost plan.

The read boundary is mostly clean: callers consume records/accessors rather than opening the packaged JSON. The physical contract still leaks through `DATA_PATH` and three writers: `catalog_price_authoring.set_catalog_model_price:108–112` directly reads JSON as its base snapshot; `sync_capabilities.sync_capabilities:188–213` updates that JSON; historical `scripts/migrate/seed_model_catalog.py:150–205` can replace the entire JSON with `--write --force`. These are authoring seams, but currently only seed regeneration propagates packaged JSON edits into the default runtime floor. `catalog_store.py:2` still calls JSON the authoring home, while runtime defaults to SQLite/seed. This is a **dual representation requiring the existing equivalence guard**, not two independently authoritative datasets.

Recommendation: retain SQLite runtime plus reviewable JSON/seed generation for this implementation; do not reverse the migration. At 64 models SQLite is not needed for speed: whole-file loading plus Python scanning would be adequate. Its value is normalized alias uniqueness, provenance and a future transactional local layer. Costs are generation/build machinery, JSON-in-SQL nested facts and multiple authoring paths. Make one authoring operation regenerate/verify the seed atomically; route all physical reads/writes behind `catalog_store`; maintain a disposable binary. No data/storage change is made in G0.

### Schema interpretation and named unknowns

`MODEL_CATALOG_COMPLETENESS_CONTRACT` is declared once in `src/spendguard/store/reference_data/model_catalog.py:60`. No catalog values were changed. Required factual cells must be known, rather than merely having a key: zero prices and false booleans are filled, null/blank containers are not. Non-empty aliases are required to reproduce the synonym gap requested by the brief; their semantic correctness is outside this deterministic phase.

Legitimately optional: `retired_alias_of` (only retired redirects), `price_error` (only recorded failures), `provider_base` (only designated provider fallback), `billing_exempt_reason` (only exempt rows), and populated lane maps (only supported subscription lanes; an empty map explicitly declares none). Nullable `reasoning.floor` and `reasoning.reasoning_floor` express no configured floor, rather than missing reasoning support. Cache and batch price modifiers are optional because those billing products need not be offered; absence does not prove unsupported or free. Optional capability booleans and embed batch limits are not universally applicable; absent capability facts are **cannot tell**, not complete. No semantic capability inference was used.

Applicability is declared mechanically in the verifier: `capabilities.mode=embedding` exempts chat output ceilings, reasoning controls and vision requirements; a nonempty `billing_exempt_reason` exempts metered billing/API-limit requirements. Unknown/missing mode is not treated as an exemption. Structural/type checks still inspect any present exempt cells. The historical required-gap list reports absent required subtrees once at the parent; G2 corrects the verifier to report their required descendant cells too. The census above counts every missing descendant.

**Required gaps: 213 cells across 64 models. Malformed present cells: 0.** The null/empty/missing census is larger than the required-gap count because it includes optional and inapplicable cells; none of those absences is counted as factual knowledge.

Run the repository virtualenv interpreter with `PYTHONPATH=src` and a temporary `SPENDGUARD_HOME`: `python tests/test_model_catalog_completeness.py`. The verifier reads the gateway's declared contract and logical authored/floor snapshots and makes no network/LLM calls. Ordinary tests fail on malformed declared cells, undeclared top-level/nested fields, id/key mismatch, any authored/runtime disagreement, or lost descendants in the per-path denominator. Mutation checks prove required top-level omissions, missing required subtrees and invalid date/alias shapes are detected. The whole-model denominator is printed for both snapshots.

This repository uses script-style tests discovered by `tests/test_runner.py`. The verifier's standalone entrypoint starts pytest on its own file with `--noconftest` and cleared suite addopts, so the required-cell assertion uses literal `xfail(strict=True)` in that protocol. Ordinary integrity checks remain outside the expected failure. Phase 1 must remove the marker when all required facts are filled. The verifier does not claim semantic truth, synonym correctness, external provider verification, or temporal histories absent from the storage schema.

G0 did not run the broad suite. G2 uses the repository's full script runner, which may construct the disposable SQLite build artifact from the unchanged reviewable seed. ## 3. Temporal framing
| Datum | Observed date framing | Missing / limitation |
|---|---|---|
| Model row freshness | `as_of` populated **64/64** | A last-change observation is not an effective interval; mixed tracked facts share one stamp |
| Prices | `price` nonnull **62/64**, all **62/62** carry source strings and a `verified` key; only **60/62** have nonnull verification dates | **0/62** authored prices have `valid_from` or `valid_until`; **0/64** records have `price_intervals` |
| Output ceilings | Object **61/64** | **0/61** objects carry `verified`; zero effective intervals |
| Context windows | Field present **61/64**, nonnull object **40/64**, verified **7/40** | Zero effective intervals; unknown must remain named |
| Capabilities | Objects **34/64** | Zero top-level capability `verified` dates and zero effective intervals; some nested facts carry provenance |
| Retirement / aliases | One nonnull `retired_alias_of`; three nonempty alias lists | No alias/retirement effective interval |
| Vendor limits / conversion metadata | Seven vendor rows, plus conversion/cache sections in same seed | Provenance observations do not establish historical start/end validity |

Temporal **code already exists**, contradicting any claim that this capability must be built from scratch. `catalog_store.price_for_date_from_record:489–515` selects `[valid_from, valid_until)` intervals; a legacy price is assigned a synthetic start from `verified` or `as_of`. `catalog_price_authoring._catalog_price_updates_for_verified_rate:41–69` closes an open interval and appends a changed price; `set_catalog_model_price:134–139` writes `valid_from=verified`. This equates observation date with effective date unless explicitly corrected, so it cannot prove historical billing truth. Furthermore `catalog_schema.sql` / `MODEL_STORAGE_FIELDS` (`catalog_store.py:224`) contain **no `price_intervals` column**, and seed generation's field contract does not include it: an interval-bearing record is not round-trippable through the shipped physical schema today. Local JSON overlays can carry the field, but that does not complete SQLite support.

Recommended schema: retain immutable observations (`verified`, source) separately from provider-effective `valid_from` and nullable exclusive `valid_until`, preserving all price components per interval. Require exactly one open current interval only where currently billable; record unknown effective dates as unknown rather than treating verification as proof. Add corresponding versioned histories for caps/capabilities and alias retirement, keeping lane configuration/learned observation time separate. Extend storage, generator, query API and round-trip tests together before populating histories. No historical start dates are invented here.

4. `912043b7` introduced the SQLite split; seed alias rows preserve the authored lists. `3115d502` added two TypeSafe models, including `jev-latest` / `jev-preview` on `jev-1.14.0`, bringing the snapshot to **64 models, three populated lists, four alias strings**.

Current state: **61/64 alias lists empty; 62/64 retirement cells null and one missing; one nonnull retirement**. Null retirement is legitimate for a non-retired canonical record; absence of aliases cannot establish that no accepted synonym exists. A scan of all **14 first-parent catalog-changing snapshots** from introduction through HEAD found **zero removed alias strings** on surviving model ids. No observed history change emptied a previously populated alias list. Recurrence hazard: the migration seed's `build()` always emits empty aliases, and `--write --force` replaces the complete document after taking a backup (`scripts/migrate/seed_model_catalog.py:186–205`). It is explicitly one-time/refuses an ordinary overwrite. `sync_capabilities.py:203–213` instead merges capability updates into existing records and does not deliberately replace aliases. Do not blame that sync or the reorg for alias erasure without contrary evidence.
